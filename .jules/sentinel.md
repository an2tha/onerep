## 2025-05-15 - Unprotected Data API and Improper ID Validation
**Vulnerability:** The `data-api` Express server had no authentication on its `/api/v1` routes, allowing anyone with the URL to access and search the internal food and exercise databases. Additionally, ID parameters were not strictly validated, and initial attempts to fix this used a MongoDB-specific hex regex for a PostgreSQL-backed system.
**Learning:** Monorepo microservices can sometimes be overlooked in security audits, especially when they are intended to be "internal" but are exposed via public routes. It's critical to verify the actual ID formats used by the underlying database (e.g., PostgreSQL serial IDs or alphanumeric slugs) before applying strict validation regexes.
**Prevention:** Always implement a baseline authentication layer (like API key validation) for all API services. Use generalized but strict regexes (e.g., `/^[a-zA-Z0-9\-_]+$/`) for IDs that may support multiple formats until a specific format is strictly enforced.
